## Зачем это нужно

Стандартный рабочий процесс геолога-структурщика: массив отснят фотограмметрией
или лазерным сканером, получена 3D-модель обнажения, и по ней нужно снять
ориентировки трещин, их протяжённость и расстояния между ними. Вручную это
делается рулеткой и горным компасом на самом обнажении — долго, местами
физически недоступно и без возможности перепроверить.

ScientiaJoints переносит эту работу на модель. Вы кликаете по трещинам прямо во
вьюпорте, аддон считает азимут падения, угол падения, площадь, длину и
расстояния, а затем строит гистограммы распределения и стереограмму плотности
полюсов и выгружает всё в CSV для дальнейшей обработки.

**Что можно решать:**

- **Картирование трещиноватости.** Разметить системы трещин на обнажении,
  присвоить каждой код (`J1`, `J2`, разлом и т.д.) и увидеть, как они
  группируются на стереограмме.
- **Выделение систем трещин.** Плотность полюсов на стереограмме показывает
  максимумы — это и есть системы; коды и цвета позволяют проверить разбиение
  визуально на самой модели.
- **Замер расстояний между трещинами (spacing).** Линейные замеры
  перпендикулярно системе дают распределение расстояний — вход для оценки
  блочности массива.
- **Протяжённость трещин.** Трассы измеряют реальную длину трещины по
  поверхности, а не хорду между её концами.
- **Оценка устойчивости.** Ориентировки и протяжённости — исходные данные для
  кинематического анализа откосов и подземных выработок.

## Три инструмента замера

Все три живут в тулбаре 3D-вида, рядом со штатной линейкой Blender.

| Иконка | Инструмент | Что делает |
|---|---|---|
| ![](docs/icons/scientiajoints.measure.png) | **Scientia Measure** | Два клика — линейный замер (расстояние, азимут, падение, `dx/dy/dz`). Потянуть за середину отрезка — появляется третья точка и замер становится плоскостью. |
| ![](docs/icons/scientiajoints.polygon_measure.png) | **Scientia Polygon Plane** | Замкнутый контур по границе трещины. Плоскость подбирается по всем точкам методом наименьших квадратов, считается площадь и ошибка подбора. |
| ![](docs/icons/scientiajoints.trace_measure.png) | **Scientia Trace** | Открытая полилиния по трещине. Длина — сумма сегментов, поэтому извилистая трещина измеряется по себе, а не по хорде между концами. |

Управление у полигона и трассы одинаковое: клики добавляют точки,
`ПКМ` / `Enter` / `Space` завершают, `Backspace` / `X` / `Del` убирают
последнюю точку, `Esc` отменяет. `Ctrl` временно переключает привязку к
геометрии. У полигона замыкание ещё делается кликом по первой точке; у трассы
замыкания нет — у неё два конца.

## Установка

На каждую версию публикуются два архива. Они ставят пакеты для графиков
по-разному, поэтому если один не встал — работает второй.

### Extension (рекомендуется)

`ScientiaJoints-<версия>-extension.zip` несёт `matplotlib` и `mplstereonet`
внутри архива. Blender распаковывает их сам: без pip, без обращения к
репозиторию пакетов, без сети и с коротким путём установки.

1. Скачайте extension-архив. Архив `Source code` с GitHub не является
   устанавливаемым пакетом.
2. Перетащите ZIP в окно Blender либо
   `Edit > Preferences > Get Extensions > Install from Disk`.

Это вариант для корпоративной сети, которая блокирует индексы пакетов, и первое,
что стоит попробовать, если не появляется стереограмма.

### Legacy add-on

`ScientiaJoints-<версия>.zip` ставится через
`Edit > Preferences > Add-ons > Install from Disk`. Пакеты для графиков аддон
доустанавливает сам: сначала из вложенных в архив wheel-файлов (сеть не нужна),
и только если это не удалось — с PyPI. Установка идёт в фоне, Blender не
подвисает; ход и результат видны в панели аддона.

### Если графики не появились

Нажмите иконку `i` в заголовке панели ScientiaJoints — откроется отчёт
диагностики. Он называет конкретную причину и что делать. Самые частые:

- **Пакеты не установились.** Панель покажет, каких не хватает, и предложит
  кнопку установки.
- **Ограничение пути в 260 символов в Windows.** `matplotlib` читает свои
  data-файлы при импорте; за этой границей файлы есть, но не открываются.
  Extension-сборка держит путь коротким.
- **Второй numpy.** Blender везёт свой; вторая копия рядом даёт ошибки бинарной
  совместимости в `matplotlib`.
- **Сеть, блокирующая или инспектирующая HTTPS.** Отчёт различает ошибку
  сертификата, отказ прокси, таймаут и недоступный индекс.

## Рабочий процесс

1. Загрузите модель обнажения и, при необходимости, включите
   `Chart Appearance > Blender View > Rock Inspection` — вьюпорт переходит в
   Rendered, а модель освещается скользящим светом под малым углом, который
   выводит трещины и уступы в тень. Так структура читается лучше, чем при
   освещении «в лоб».
2. Выберите инструмент в тулбаре и размечайте трещины.
3. В `Measurement Info` присвойте замеру код и описание. Коды получают свой цвет
   и переключатель видимости, так что системы трещин можно смотреть по одной.
4. `Azimuth Correction` вводит поправку, если модель развёрнута относительно
   истинного севера: `Real` — истинный азимут ориентира, `Model` — его азимут в
   модели.
5. Кнопки сверху панели открывают гистограмму рёбер, стереограмму и гистограмму
   трасс. Рядом с каждой — тумблер автообновления; одновременно работает только
   один.
6. `Export` выгружает CSV с рассчитанными величинами и TXT с сырыми
   координатами. Перед экспортом `.blend` должен быть сохранён — путь выгрузки
   строится рядом с ним.

### Производительность на больших сценах

Оверлей рассчитан на десять тысяч замеров. Геометрия 3D-прохода в мировых
координатах и кэшируется, поэтому вращение сцены её не пересчитывает. Экранные
элементы — точки и подписи — пересобираются каждый кадр, поэтому у них есть
бюджет: `Overlay Style > Viewport Budget`. Рисуются те, что ближе к центру вида,
плюс активный замер и тот, что под курсором. Поднимите бюджет, если нужно видеть
больше сразу; опустите, если вьюпорт подтормаживает.

## Сборка релиза

Нужен Python 3.10+ и полная копия репозитория. Blender для сборки не требуется —
только для проверки готового архива.

**1. Версия.** Задаётся одной командой, и это единственный поддерживаемый способ:

```powershell
python tools\version.py 3.4.2
```

Версия живёт в `blender_manifest.toml`. Blender читает `bl_info` из
`__init__.py` через `ast.literal_eval` ещё до импорта аддона, поэтому вторую
копию нельзя вычислить — команда пишет оба файла. `tools\build_release.py`
откажется собирать копию, где они разошлись. Без аргумента команда печатает
текущую версию.

**2. Запись в `CHANGELOG.md`.**

**3. Wheel-файлы для вложения в архив.** Запускать питоном **Blender**, чтобы
теги совпали с целевой версией:

```powershell
& 'E:\SteamLibrary\steamapps\common\Blender\5.2\python\bin\python.exe' tools\fetch_wheels.py --platform win_amd64 --python-version 3.13
```

`--all-platforms` собирает архив, который встанет на Windows, Linux и macOS.
Папка `wheels/` не коммитится и пересобирается на каждый релиз.

**4. Тесты и проверка компиляции** из корня репозитория:

```powershell
python -m unittest discover -s tests -v
```

**5. Сборка обоих архивов:**

```powershell
python tools\build_release.py
```

Пишет `dist/ScientiaJoints-<версия>.zip` (legacy) и
`dist/ScientiaJoints-<версия>-extension.zip`, проверяет структуру пакета,
синтаксис Python, наличие нужных символов в модулях и согласованность
манифеста с вложенными wheel-файлами, печатает SHA-256. `--format legacy` или
`--format extension` собирают только одно.

**6. Проверка extension-архива самим Blender:**

```powershell
& 'E:\SteamLibrary\steamapps\common\Blender\blender.exe' --command extension validate "dist\ScientiaJoints-$(python tools\version.py)-extension.zip"
```

**7. Установка в чистый профиль** перед публикацией: направьте
`BLENDER_USER_RESOURCES` на пустую папку с **коротким** путём.

Legacy-архив сохраняет wheel numpy, потому что `pip --target` разрешает
зависимости, не глядя на уже установленное, и офлайн-установка иначе падает.
Extension-архив его выбрасывает: Blender везёт свой numpy, а вторая копия
рискует бинарной несовместимостью.

### Артворк

Иконки инструментов Blender берёт из `icons/*.dat` — это списки треугольников,
а не картинки. Артворк описан вектором в `tools/build_tool_icons.py`:

```powershell
python tools\build_tool_icons.py --preview preview.png
python tools\build_tool_icons.py --png --png-size 1024
python tools\build_logo.py --size 512
```

`.dat` закоммичены, поэтому обычная сборка ничего не требует; скрипт нужно
перезапустить после правки кода отрисовки. `--png` пишет прозрачные PNG для
презентаций и документов, `tools/build_logo.py` — логотип аддона.
`tests/test_tool_icons.py` падает, если закоммиченные `.dat` разошлись с
исходником, если формат битый или если инструмент незаметно откатился на
встроенную иконку линейки.
